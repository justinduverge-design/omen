## Provider certification rule

Build 10 is not "provider complete" because a shared route exists. Each included feature must record
an outcome for ESPN, Yahoo and Sleeper:

- `PASS-DEVICE` — authenticated physical-device journey succeeded;
- `PASS-CONTRACT` — source/contract/fixture proof only, still awaiting device proof;
- `DEGRADED` — useful behavior with an explicit limitation;
- `UNAVAILABLE` — intentionally blocked with an honest reason;
- `FAIL` — expected behavior broke;
- `UNPROVEN` — evidence was not run.

Only `PASS-DEVICE`, an explicitly accepted `DEGRADED`, or an intentionally designed `UNAVAILABLE`
state may be described as release-ready. `PASS-CONTRACT` does not promote itself.

## Definition of done

- One Build 10 customer outcome is named in one sentence and all unrelated candidates remain out.
- Required backend, native unit and native journey checks pass for the selected slice.
- ESPN, Yahoo and Sleeper each have a recorded terminal state for every included core action.
- The paired iPhone is built, installed, launched and walked against real authenticated data.
- Screenshots/logs/build identity are captured without secrets or private league data in the repo.
- Fresh independent review finds no open P0/P1 in the candidate.
- Rollback/exclusion behavior is written before freeze.
- Monday-afternoon freeze and Tuesday canary are observed.
