12. **`connected` ≠ `usable` for provider connections.** `GET /api/platforms` reports whether a `platform_connections` row is active with a league id. Whether that connection can actually serve data is a different predicate (`isOmenReadyConnection()` / `hasUsableYahooToken()` in `src/services/omenReadiness.js`) and is surfaced through `/api/dashboard/summary` tool statuses. Never cite `connected: true` as evidence that a provider works; cite the tool status.

13. **Required security controls are mandatory operating practice, not optional founder-approval items** (decided 2026-08-22). A control such as leaked-password protection, least-privilege secret scoping, credential rotation after possible exposure, log containment, or release security evidence remains required until directly evidenced. Founder-only access identifies who must execute a dashboard or credential action; it does not turn the control into a discretionary product choice. Any exception requires its own explicit, reasoned founder decision naming the risk, duration, mitigation, and closure trigger.

15. **Justin Duverge Catalino is the sole owner of record for every Omen role that requires a named person** (declared 2026-08-27). He is the only person working on this company. Where any item, runbook, gate, or Definition-of-Done clause requires a *named owner* — rollback owner, incident owner, release owner, security owner, data owner, on-call, escalation contact, accountable approver — **that person is Justin, by default and without a per-item declaration.** Agents must stop pausing work to ask who the owner is, and must stop recording "owner not named" as an open blocker.
    - **Revisit trigger, and it is the whole condition:** the moment anyone else works on this company — employee, contractor, co-founder, agency — this fact is void and every named-owner clause must be re-derived. It is a statement about a one-person company, not a permanent delegation.
    - **What this fact does NOT do, stated so it is not quietly over-read.** It answers *who is accountable*. It does not answer *whether an action is authorized*, and it does not dissolve gates that exist for reasons other than accountability:
      - **Applying SQL** stays the gated sequence (fact #8). That gate is about blast radius and reviewability, not about who to blame.
      - **Production changes, deploys, provider credentials, and store actions** still need their own explicit approval per action. Being the owner is not standing consent.
      - **"Required control" items** (fact #13) stay required. A sole owner cannot waive a control by being the only person who would notice.
    - **Practical effect:** an item whose only remaining clause is "name an owner" is **closed**, not blocked. An item that also needs an action performed still needs the action.

Product analytics are **built in-house** — events counted into Supabase, read by the Founder Digest. **No third-party analytics SDK** (PostHog, Amplitude, or otherwise) may be introduced without an explicit reversal of this decision; the founder chose privacy over a clickable dashboard knowingly, and "a dashboard would be handy" is not a reversal. Beta reports are summarized by the **local Ollama** path only. `AI_PROVIDER=cloud` stays fail-closed at `cloud_disabled_zero_budget` and the public-host guard in `src/services/llm.js` stays; relaxing either is a founder budget decision **and** an egress decision about other people's words, never a config change.

18. **Breach detection is not claimable and must not be built as though it were** (decided 2026-08-31). "We would know if user data was taken" cannot be cashed. The alert surface is a finite list of genuinely detectable signals: RLS denial spikes, failed-authentication floods or anomalous single-account row volume, service-role key use from an unexpected origin, **backup failure**, and credentials appearing in logs. Only two categories may interrupt the founder — the app is down, and user data is at risk as defined by that list. Everything else waits for the digest.

"Try Demo" and every `.demo` state branch (League, Trade, Decision Brief, League Switcher) come out — demo data was a permanent "is this real?" surface and a second set of states to keep honest. The 32-team palette system has **no native screen and is not to get a partial one**: the prior build was judged wrong and the infrastructure to do it properly may not exist. Postponed, not cancelled. Do not reintroduce either quietly.
