# Facts of Record — Omen (L2)

**valid-as-of:** 2026-06-15
**Purpose:** L2-specific facts. Inherits L0 and L1 facts.

## Active facts

1. **Omen is free indefinitely** (decided 2026-06-15, reaffirmed 2026-07-12). No billing gates in `Blueprints/definition-of-done.md`. Stripe is not used on this product at all — the `stripe` package, `/api/stripe/*` routes, `requireSubscription` middleware, `subscriptions` table, and `users.is_subscribed` column were fully removed 2026-07-12 (see decision log). Do not re-add billing/paywall code without a new explicit decision.
2. **Both Claude and Codex are lane-agnostic** with soft lean. Either agent can pull any item from `Direction/agent_inbox.md`.
3. **Inbox selection mechanic** — agent reads pin first (`📌 [item]`), otherwise selects up to 5 items with `Status: READY` across all lanes in `Direction/current_sprint.md`, ordered by the selection rule, records a `Claim:` on the single item it starts, overwrites the inbox, and surfaces to Justin any item whose `Blocked by:` line is not `None`. A shortlist is not authority to claim five. Task states, `Claim:`/`Evidence:` requirements, `Blocked by:` and `Unblock:` grammar, closure types, the selection rule, and WIP rules are defined in **`Direction/status-model.md`** — the operational mirror this repo carries so it works in standalone clones and CI. L0 holds the shared canonical source (`Blueprints/agent-modules/status-model.md`, `SCHEMA_VERSION 1.0.0`). There is no silent "L0 wins" rule: when both copies are available, any difference in schema version or operational content is a **blocking Truth Gate failure** — halt and report. In a standalone Omen checkout the local mirror is operative. The session flow lives in the kickoff prompt (`Blueprints/prompts/kickoff-l2.md`) and `Blueprints/prompts/HOW-TO-RUN-THE-LOOP.md`. This replaced the retired checkbox mechanic on 2026-07-29.
4. **`Blueprints/specs/page-system.md` is the contract** for every Phase 1.4–1.12 frontend item. Per-page typography, accent, palette, copy anchor, light/dark parity rules. Landed 2026-06-15.
5. **DoD is now per-type** at `Blueprints/done/` — pointer at `Blueprints/definition-of-done.md`, 7 type files (feature, page, release, security, recommendation, design, content-marketing), and `LEDGER.md` for closure tracking. Evidence discipline: point to evidence, don't paste command output.
6. **ESPN cookie values never logged, displayed, or echoed.** Anywhere. Ever.
7. **Mock data is always labeled.** Never silently mixed with live data.
8. **Prepared Omen Supabase SQL is never applied by an agent.** SQL authored in `sql/` is review-only source. Applying it to staging or production is a separately gated Justin action, in order: explicit approval → staging application → verification → production application. Authoring SQL in the repo and applying it to a live database are distinct acts; only the first is agent work. Evidence in `Direction/decision_log.md`: the Phase 1 ADP/scoring schema entry ("review-only SQL … No Supabase SQL was applied, no migration history was changed, and no production action happened"); the Stripe-removal entry, which added real `drop table` / `alter table drop column` statements to `sql/omen_rls_security.sql` as *source only* and records that they "still need to be run against production Supabase separately"; and the Tuesday-scoring entry, where founder approval to proceed explicitly "removes the founder-approval blocker, not the dry-run step itself."

9. **Draft Assistant is sidelined to the 2027 season** (decided 2026-08-11, extending the 2026-08-05 cut from 1.0). It is not a 1.0 feature and must not appear in onboarding copy, legal copy, navigation, or the advertised tool list in `/api/dashboard/summary`. **The implementation is preserved, not deleted** — 2027 ships it on a Slops-built ADP and `src/services/adp.js`, `sleeperDraft.js`, and `sleeperDraftAccess.js` are that head start. Removal is from the reachable surface only. Tracked as `P1-DraftAssistantSideline`.
   - **Amended 2026-08-14 (founder-approved).** A **single factual forward-looking mention is now permitted** on the marketing site and in a clearly-labelled in-app "not in this version" note. The locked wording is **"2027 fantasy draft"** — the founder's framing is "next fantasy year's draft". **Never** "coming soon", never a specific month, and never phrasing that implies it ships in this version. **Store metadata remains excluded from this permission:** Apple and Google expect listing copy to describe what the app does today, so advertising an unreleased feature there risks a review rejection — a different and larger risk than saying it on our own site.

10. **Omen-dependent acceptance has a season-start floor.** `GET /api/dashboard/summary` returns `omen_of_the_week: "off_season"` outside the NFL regular season, produced by `isOffSeason()` in `src/services/nflSchedule.js`. This is correct behavior, not a defect — but it means any item whose acceptance includes *Omen recommendations* (F6, F7, F8, and anything downstream of them) **cannot fully pass until the 2026 regular season opens.** The non-Omen halves are testable year-round. Do not record such an item as VERIFIED on its non-Omen half alone; split the evidence and state which half was proven.

11. **Yahoo API access was re-approved in early 2026-08.** The developer application is live again. This is separate from — and does not fix — the stale stored OAuth token described in `Direction/known_issues.md`.

12. **`connected` ≠ `usable` for provider connections.** `GET /api/platforms` reports whether a `platform_connections` row is active with a league id. Whether that connection can actually serve data is a different predicate (`isOmenReadyConnection()` / `hasUsableYahooToken()` in `src/services/omenReadiness.js`) and is surfaced through `/api/dashboard/summary` tool statuses. Never cite `connected: true` as evidence that a provider works; cite the tool status.
