## 2026-10-14 paired-phone Trade walk

The founder built from Xcode and supplied four physical-iPhone screenshots. They are valid evidence
for the installed binary, but not Build 12 verification: the visible sentence `Standard scoring.
Connect a league to use your own settings.` exists on `main` at `633596b7` and is absent from the
Build 12 branch. The Build 12 checkout also lacked its ignored `Local.xcconfig`, so opening the right
project without restoring that local link would have produced a second misleading provider-disabled
build.

The walk still established real product findings:

- **P1 — Trade does not match the approved league-aware composition.** The default surface remains
  free-text manual entry. The active league, the user's fixed side, opponent selection, and roster
  builder are not the primary mental model; the real-roster path is hidden behind a conditional link.
- **P1 — Find can capture nil league context while the directory is loading.** It then says
  `Connect a league first` before a Find request occurs. Build 12 now re-reads the directory, recovers
  its authoritative active league, separates connected-but-unselected from truly empty, and gives a
  genuinely empty account a working Connect action. Focused `TradeFindFlowTests` pass 14/14.
- **P1 — name-only manual players are not canonical evidence.** Typing Gibbs and Robinson and
  pressing Add created players without provider identity, position, team or projection, then allowed
  Compare to reach an unsurprising two-projection `Not yet` result. Require canonical selection or an
  unambiguous server resolution before this path can claim comparability.
- **P1 — recovery copy is too coarse.** `Connect this league` cannot be the remedy for lost context,
  unsupported personalization and unresolved players alike.
- **P2 — the custom keyboard Done pill overlaps the form on the physical phone.** Retain dismissal,
  but use a native accessory or remove the redundant pill after device verification.

Device-install provenance is now guarded in `scripts/install-latest-ios.sh`: it resolves its checkout
from the script path, requires the ignored local config, isolates Derived Data by commit, fails on an
Xcode build error, and prints the absolute root, branch, commit, bundle and app build before install.
No phone install, provider call, push, merge or Apple action was performed for this repair.

The next coherent Trade slice is therefore:

1. make the connected league-aware builder the primary `Build a trade` mode;
2. keep free text as an explicit `Type a trade` mode, but require canonical players;
3. anchor the user's team, exclude it from opponent choices, and show the chosen opponent(s);
4. derive every remedy from the actual missing context/evidence reason;
5. rebuild from the exact Build 12 checkout and repeat the paired-phone journey with Yahoo or
   Sleeper first. ESPN fresh-login/Rhody remains deferred.

## Provider certification rule

Build 12 is not "provider complete" because a shared route exists. Each included feature must record
an outcome for ESPN, Yahoo and Sleeper:

- `PASS-DEVICE` — authenticated physical-device journey succeeded;
- `PASS-CONTRACT` — source/contract/fixture proof only, still awaiting device proof;
- `DEGRADED` — useful behavior with an explicit limitation;
- `UNAVAILABLE` — intentionally blocked with an honest reason;
- `FAIL` — expected behavior broke;
- `UNPROVEN` — evidence was not run.

Only `PASS-DEVICE`, an explicitly accepted `DEGRADED`, or an intentionally designed `UNAVAILABLE`
state may be described as release-ready. `PASS-CONTRACT` does not promote itself.
