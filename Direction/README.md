# Omen Direction

What Omen is doing and why: the product, the rules, the current sprint, decisions, known issues and release
records. Start with `map.md`.

| File or folder | What it is |
|---|---|
| `map.md` | **Start here.** One page: what Omen is, the rules, what's happening now, and what to read for each kind of task |
| `context.md` | The product and its tool hierarchy (Trade Analyzer, Omen of the Week, League/Waivers, Command Center) |
| `facts-of-record.md` | The rules that never bend, each with its history. A rule lives here once |
| `current_sprint.md`, `agent_inbox.md` | The active work queue and the pinned task |
| `release/builds/` | One record per beta build: what was wrong, what got fixed, PRs, known issues, tester notes |
| `release_readiness.md`, `release/` | Readiness for the App Store and TestFlight, and the upload runbook |
| `known_issues.md` | Open problems (resolved ones are in `known_issues-resolved.md`) |
| `decision_log.md` | Every decision, dated. Search it; it is long |
| `shipped.md` | Merged and open PRs by area, generated by `node scripts/shipped.js` |
| `roadmap.md`, `omen-1.0-plan.md` | Longer-range plans |
| `YYYY-MM-DD-*.md` | Dated plans, device walks and readiness checks (for example `2026-10-20-build-12-plan.md`) |
| `reviews/` | Dated reviews and audits |
| `product/`, `intents/`, `policies/` | Product bar, captured feature intents, and provider disclosure policy |

When a dated file and `map.md` disagree about "now", `map.md` and the newest file in `release/builds/` win.
