# ADR-005: Platform Adapter Pattern

**Date:** 2026-05-12
**Status:** Accepted (Implemented)
**Deciders:** Justin Duverge (CEO/Founder), Claude (Architect)

## Context

Omen supports Yahoo, Sleeper, and ESPN — three platforms with entirely different APIs, auth models, and data shapes. Without a normalization layer, downstream services (VORP, optimizer, Start/Sit) would need platform-specific logic, creating a maintenance burden and making it impossible to add future platforms cleanly.

## Decision

Each platform has an adapter (`src/adapters/yahoo.js`, `src/adapters/sleeper.js`, `src/adapters/espn.js`) that normalizes its output to identical `roster` and `player` shapes. All downstream services consume the normalized shapes only — they never know which platform supplied the data.

## Consequences

**Positive:**
- Adding Fantrax or NFL Fantasy requires only a new adapter, not changes to the intelligence layer
- VORP, optimizer, and Start/Sit are platform-agnostic
- Testing is isolated per adapter

**Negative / Trade-offs:**
- Normalization loses platform-specific metadata that isn't in the normalized shape
- Adapter maintenance is ongoing as platform APIs change

**Constraints:**
- `player_key` must be prefixed: `yahoo:{id}`, `sleeper:{id}`, `espn:{id}`
- Downstream services must not import or reference platform-specific adapters directly
- Cross-platform IDs (`yahoo_id`, `espn_id`, `gsis_id`) are included as nullable fields
