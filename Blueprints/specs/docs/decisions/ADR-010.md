# ADR-010: VORP + Trade Analysis A+B Model

**Date:** 2026-05-11
**Status:** Accepted (Implemented)
**Deciders:** Justin Duverge (CEO/Founder), Claude (Architect)

## Context

Trade Analyzer needed a defensible value model. Black-box recommendations or "gut feel" projections violate the Omen accuracy standard (A1). The A+B model separates the math (A = VORP delta + positional scarcity) from the narration (B = LLM explanation), keeping the calculation transparent and the output readable.

## Decision

Trade analysis uses a two-tier model: Tier A computes the win probability delta and positional scarcity value for each side of a trade using VORP v2. Tier B uses the LLM (Gemma) to narrate Tier A's output in plain English. The recommendation is always grounded in Tier A — Tier B only explains it.

## Consequences

**Positive:**
- Calculations are explainable and auditable (A1 satisfied)
- LLM narration makes results readable without making them the source of truth
- VORP logic can be updated independently of the explanation layer
- Users can see what drove the recommendation (projection edge, scarcity)

**Negative / Trade-offs:**
- VORP accuracy depends on the quality of projected points from the platform adapters
- If projections are null or stale, VORP delta degrades

**Constraints:**
- VORP assumptions must be documented explicitly — never presented as certainty
- The A model (math) must produce a result even if the B model (LLM) times out
- Position scarcity thresholds must be defensible and documented in `vorp.js`
