# ADR-007: LLM Backend-Only Reasoning Engine

**Date:** 2026-05-15
**Status:** Accepted
**Deciders:** Justin Duverge (CEO/Founder), Claude (Architect)

## Context

Corvus uses a local Gemma 3 model (via Ollama on Hostinger KVM2) as a reasoning and explanation layer. The question was whether the LLM should be user-facing (chat interface) or backend-only (narrates deterministic math). A user-facing LLM creates chatbot expectations, introduces hallucination risk at the product surface, and is incompatible with the "no-chatbot" doctrine.

## Decision

The LLM is backend-only. It narrates the output of deterministic football math — VORP deltas, projection edges, matchup signals — in plain English. It does not accept user prompts, does not drive product logic, and is not exposed via any user-facing interface.

## Consequences

**Positive:**
- Prevents hallucination from reaching users directly
- LLM output is always grounded in structured data (VORP, projections, matchups)
- Product interface remains clean and action-oriented
- LLM_BASE_URL is never exposed in any API response

**Negative / Trade-offs:**
- LLM improvements don't create new user-visible features without product changes
- Model quality still matters — bad narration erodes trust even if the math is right

**Constraints:**
- `LLM_BASE_URL` must point to a private or firewall-restricted Ollama instance
- The LLM may time out gracefully — all LLM-narrated fields must have non-LLM fallbacks
- No user-facing input field may be wired to the LLM without a full product decision from Justin
