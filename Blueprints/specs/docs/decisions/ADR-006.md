# ADR-006: ESPN Cookie Auth Risk

**Date:** 2026-05-12
**Status:** Accepted (Mitigated)
**Deciders:** Justin Duverge (CEO/Founder), Claude (Architect)

## Context

ESPN's fantasy API does not offer a public OAuth flow. The only viable authentication method requires the user's `SWID` and `espn_s2` cookies, extracted manually from their browser. Storing, transmitting, or logging these cookies creates a meaningful security risk — they grant full access to the user's ESPN account.

## Decision

ESPN cookies are accepted as the only feasible auth method. Risk is mitigated by: storing cookies exclusively in Supabase Vault (not the database, not logs, not query params), never logging or exposing cookie values, requiring masked inputs in the UI, and gating the entire ESPN connection UI behind `VITE_ESPN_ENABLED` until a policy disclosure is approved.

## Consequences

**Positive:**
- ESPN support is possible without waiting for ESPN to publish an OAuth API
- Users who want ESPN can opt in with informed consent

**Negative / Trade-offs:**
- Cookie-based auth is fragile — cookies expire and may change format
- Vault secret management adds backend complexity
- User must manually extract cookies from their browser

**Constraints:**
- Cookie values must never appear in logs, error messages, query params, or response bodies
- `VITE_ESPN_ENABLED` must remain `false` in production until Justin reviews the disclosure copy
- ESPN cookie handling requires explicit Justin approval before any change to the auth flow
