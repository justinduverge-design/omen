## A.1 — Audit findings (cross-cutting)

### Viewport meta

[frontend/index.html:5](frontend/index.html:5) — was `width=device-width, initial-scale=1.0`.
**Risk:** without `viewport-fit=cover`, `env(safe-area-inset-*)` returns 0 on iPhone with notch/Dynamic Island, defeating any safe-area-aware padding.
**Fix applied:** added `viewport-fit=cover`.

### `webkit-tap-highlight-color`

`grep` returned **0 matches** project-wide.
**Risk:** every tap on iPhone Safari paints the default gray translucent flash over the tapped element — looks unintentional and clashes with the brand palette.
**Fix applied:** added global `-webkit-tap-highlight-color: transparent` to `html` in [frontend/src/index.css](frontend/src/index.css).

### `safe-area-inset`

`grep` returned **0 matches** project-wide.
**Risk:** any fixed-bottom element collides with the iPhone home-indicator gesture area; any fixed-top element risks overlap with notch/Dynamic Island in landscape.
**Findings:**
- [frontend/src/components/ui/HelpButton.jsx:324](frontend/src/components/ui/HelpButton.jsx:324) — floating help button is `fixed bottom-8 right-5`; `bottom-8` = 32px, less than the ~34px home-indicator gesture zone.
- `Landing` and `CorvusLanding` `<Header>` are `sticky top-0` — fine in portrait (status bar overlays cleanly), may overlap notch in landscape. Low priority.
- Drawers in `Header.jsx` and `HelpButton.jsx` use `h-full` — top/bottom may be clipped by safe areas.

**Fix applied:** raised HelpButton with `bottom: max(2rem, calc(env(safe-area-inset-bottom) + 1rem))`. Sticky headers and drawer safe-area padding deferred to Phase C if Justin reports clipping.

### Input auto-zoom on focus

iOS Safari auto-zooms when the focused input/textarea/select has `font-size < 16px`. Every routed-page input uses Tailwind `text-sm` (14px), so every form field on the site triggers an unintended zoom-in on tap.

| Component | Line | Notes |
| --- | --- | --- |
| [Login.jsx](frontend/src/pages/Login.jsx:93) | 93 | magic-link email — `text-sm` |
| [Landing.jsx](frontend/src/pages/Landing.jsx:384) | 384, 476 | hero + waitlist email — `text-sm` |
| [ConnectLeague.jsx](frontend/src/pages/ConnectLeague.jsx:99) | 99 | `FieldInput` (Sleeper username, ESPN cookies, league IDs) — `text-sm` |
| [DraftAssistant.jsx](frontend/src/pages/DraftAssistant.jsx:385) | 385, 398 | draft position/round — `text-sm` |
| [TradeAnalyzer.jsx](frontend/src/pages/TradeAnalyzer.jsx:18) | 18 | shared `INPUT_CLS` (autocomplete + position select) — `text-sm` |
| [PlatformConnections.jsx](frontend/src/components/platforms/PlatformConnections.jsx:48) | 48 | `Field` (used inside Account page) — `text-sm` |

`OmenFeedback.jsx` input already uses `text-base` (16px) — good.

**Fix applied:** scoped CSS rule in `index.css` under `@media (hover: none) and (pointer: coarse)` that forces `font-size: 16px` on `input` (non-checkbox/radio/button), `textarea`, and `select`. Touch devices only — desktop keeps Tailwind's `text-sm` density. Selector specificity (0,5,1) beats Tailwind utility classes. No file-by-file className churn needed.

### Datetime native UI

### Body scroll-lock pattern

`Header.jsx:107` and `HelpButton.jsx:131` both set `document.body.style.overflow = 'hidden'` when a drawer opens. Known iOS Safari bug: this doesn't fully prevent rubber-band scroll behind the drawer; the standard fix is `position: fixed` + `top: -<scrollY>` + restore.
**Not fixed pre-emptively** — invasive change, and only manifests if the user scrolls *inside* the drawer or rubber-bands the scrim. Flagged for Justin's iPhone test in Phase B.

### Hover-only states

Most hover styles in routed pages are decorative refinements; the underlying interaction (selection, active state) is signalled by other CSS not gated on `:hover`. One genuine hover-only case worth noting:
- [TeamTheme.jsx:363-370](frontend/src/pages/TeamTheme.jsx:363) — "Show all 32 teams" expand button uses `onMouseEnter`/`onMouseLeave` to swap text color + bottom border. On iOS the button still works (tap toggles `expanded`), but the polish is invisible.
**Not fixed pre-emptively** — minor cosmetic, defer unless Justin calls it.

### Tables / horizontal overflow

Tables in [Standings.jsx:25](frontend/src/pages/Standings.jsx:25) and [LeagueStandings.jsx:21](frontend/src/components/league/LeagueStandings.jsx:21) are wrapped in `overflow-x-auto` ✓. Football page tab strip ([Football.jsx:219](frontend/src/pages/Football.jsx:219)) also uses `overflow-x-auto` ✓.
